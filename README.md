# UTM-реестр

Веб-приложение для ведения единого реестра UTM-меток команды.

## Установка и запуск

```bash
npm install
npm start
```

Приложение будет доступно по адресу `http://localhost:3000`.

Порт можно изменить через переменную окружения `PORT`:

```bash
PORT=8080 npm start
```

Данные (реестр меток и пресеты) хранятся в JSON-файлах в папке `data/`
(`data/registry.json`, `data/presets.json`), которая создаётся автоматически
при первом запуске.

## Админ-панель

По адресу `/admin` доступна отдельная панель администратора: экспорт меток
в Excel и их удаление — больше никаких функций там нет.

Вход защищён паролем, который задаётся через переменную окружения
`ADMIN_PASSWORD`:

```bash
ADMIN_PASSWORD=ваш-пароль npm start
```

Если переменная не задана, вход в админ-панель отключён (сервер отвечает
ошибкой при попытке войти). Сессия хранится в httpOnly-cookie и живёт 12 часов.

Cookie сессии по умолчанию выставляется с флагом `Secure` — **сервер должен
быть доступен по HTTPS**, иначе браузер откажется сохранять cookie и вход не
будет держаться после перезагрузки страницы. Для локальной разработки по
обычному `http://` задайте `COOKIE_SECURE=false` в `.env` (или в переменных
окружения).

### Пароль на сервере (PM2)

Для запуска через PM2 в проекте есть `ecosystem.config.js` — он читает
переменные окружения из файла `.env` рядом с собой (сам `.env` в git не
попадает, см. `.gitignore`).

На сервере один раз:

```bash
cp .env.example .env
nano .env   # впишите ADMIN_PASSWORD=...
```

Дальше запускайте/перезапускайте так:

```bash
pm2 startOrReload ecosystem.config.js
```

Эту же команду использует `.github/workflows/deploy.yml` при автодеплое —
пароль из `.env` будет подхватываться при каждом деплое без лишних действий.
Чтобы PM2 поднимал процесс и после перезагрузки сервера, один раз выполните
`pm2 save` (и `pm2 startup`, если ещё не настроено автозапуск PM2).
